## When to Open an Issue

Open a public issue for:

- reproducible build failures
- runtime regressions
- documentation gaps
- feature requests
- non-sensitive bugs

Include:

- platform and compiler details
- Qt version
- whether you are using local or system MapLibre
- the exact command you ran
- logs, screenshots, or backtraces when relevant

## When Not to Open a Public Issue

Do not open a public issue for:

- unpatched security vulnerabilities
- secrets or credentials
- reports that include private infrastructure details

Use [SECURITY.md](/home/boots/work/phd/GCSNetworkPlanner/SECURITY.md) for those cases.

## Maintainer Expectations

This is an open-source project maintained with limited bandwidth. Responses may take time, especially for legacy-subsystem issues, but high-quality reproducible reports are much easier to triage.
